### 互斥状态与默认布局

- 旋转凝缩器状态：`mekanism:fluid_to_gas` 和 `mekanism:gas_to_fluid`。
- 农场介质状态：`mekanism:farm_gas` 和 `mekanism:farm_fluid`，避免把原机互斥的气/液介质仓当成两个可同时使用的储罐。
- 等级版的每个状态直接声明自身进程倍率后的容量，不再复用 1,000 容量的基础状态定义。
- 未显式选择状态时，自动执行只接纳基础布局中实际存在的端口所支持的状态。目录及显式状态仍保留完整配方；基础校验和机制冻结使用同一执行选择规则。

### 聚变零注入的校正

原清单把注入 0 时的倍率记作 1，实际已成形原机的取偶公式得到 **0**。CloudWorks 的端口要求正容量，因此注入 0 时不暴露水/汽端口；气体口、等离子体与热状态保持。不是偷偷改成容量 1 或 2。

## 2. 原生升级

原机自带的 SPEED、ENERGY、GAS、FILTER 及大型机 THREAD 继续按各自接受表和机制执行。按用户要求不添加降噪、锚、造石机、比较器。

补齐 MoreMachine 虚空矿物发生器的 `cloudworks:mek_thread`，物品绑定复用原生 THREAD。**该机**的原生语义为一次选择一个矿物后，数量乘 `1+有效 THREAD 数`；每 tick 用电、周期和储能不因此增加。现有大型机的 THREAD 仍增加并行数和对应储能，不能把这个策略套到虚空矿物发生器。

环境源额度与升级类型总数的无限制方向保持用户此前裁定，不恢复旧的 64/16 类型限制。

## 3. 缩小端口后的连续进料

不能仅把仓容常量缩小而留下永远装不下的整周期输入。本轮复用并扩展已有连续加工/预付燃料引擎：

- **质量机**：按一份原生放大剂配方逐次进料，按有理数换算保留已付能量进度；不再要求一次塞入 100 或 200 个物品。输入配方要求 2 件时仍每份扣 2 件。供能上限仍按原先 512 EU/t 合同。
- **TE 大燃料**：超过 4,000 mB 的总水/冷却剂消耗分成小段，以预付燃料额度持续结算；不重复烧煤、不扩大储罐、不截掉能量。锅炉同样可以保留未兑现的预付燃料额度。
- **捕鱼器**：每次抽取在原生权重池中择一，不再把各鱼种当作互相独立的命中概率。不同权重条目保留；约分只缩短等价整数权重表示，不合并条目。一个鱼饵的多周期效果保存在预付额度中，每周期进行独立抽取，输出总容量保持四槽。
- **树脂采集器**：树种为 `item_template` 配置口；真正的原生物品输入只有肥料槽，不再进出循环同一根原木。肥料的八周期额度持久化，树脂逐周期产出进入 8,000 mB 仓。
- 持久化进度绑定配方；未清零时不会借另一个燃料/放大剂配方兑换。同一机器有多个配方时可以从实际有料的配方开始。
- 先检查输出空间再扣燃料/副流体；堵塞、断供和重载均应保持资源与能量守恒。不会通过清零资源或硬塞输出绕过背压。

## 4. API 与建模边界

- `CloudworksRecipeSpec.Builder.powerDriven(joulesPerInput, inputsPerOutput)` 的输入、输出条目允许带多个单位；前者按一份输入配方计价，后者按完整输出批次兑现。正的 `extraEnergyPerTick` 在此模式下表示每执行单元的供能上限，不是第二笔费用。
- `prepaidFuel(resource, units)` 可以把一份物理燃料预付成多个工作单位，并按每个单位支付后续副流体；既可发电，也可按周期生成资源。两种产出方式不得混在同一合同中。配置模板可以作为非消耗条件。
- CRT 复用现有 `Recipes.create(...).prepaidFuel(canonicalFuel, units, joulesPerUnit)`：正的单位能量用于发电；单位能量为 0 且已声明资源输出时用于预付资源加工。`template` 声明非消耗配置条件，`energy` 在 `powerDriven` 中声明供能上限；仍由 `register(machine)` 走同一注册路径。
- 能量缓存与物品/气液处理口分开建模；本轮修正工厂已核实的原生储能公式。TE 原有云端能量缓存和发电 maxPower 速率策略不属于本轮流体仓容的定义。
- 空容器回收、树种配置、无内部罐的按面直出等仍需虚拟表达；它们不应冒充额外的原生生产仓。IC2 电解机当前使用的是 **流体** codec，不是审计清单误写的气体 codec。
