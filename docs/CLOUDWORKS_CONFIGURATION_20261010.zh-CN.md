# 云工坊配置

配置文件：游戏目录下 `config/cloudworks.cfg`，首次启动自动生成。
复用 Mek 的 `BaseConfig`、`DoubleOption`、`IntOption`、`LongOption`、`BooleanOption`。
所有项目在重启服务器 / 重新进入世界后生效；运行期间重读文件不改变正在使用的参数。

## cloudworks 分类

| 配置名 | 默认值 | 含义 |
| --- | ---: | --- |
| initialReceivingEnergyCapacity | 128000000 | 新玩家收货仓初始能量容量，单位 J |
| initialCloudEnergyCapacity | 128000000 | 新玩家云端初始能量容量，单位 J |
| initialSendingEnergyCapacity | 128000000 | 新玩家发货仓初始能量容量，单位 J |
| initialLines | 1 | 新玩家初始解锁产线数 |
| maxLines | 64 | 每个玩家可解锁产线的服务器硬上限 |
| initialMachineNodes | 64 | 新玩家每条产线初始机器节点额度 |
| maxMachineNodes | 4096 | 每条产线机器节点服务器硬上限，不计特殊节点 |
| initialWorkRate | 1 | 新玩家工作倍率 |
| maxWorkRate | 1024 | 工作倍率服务器硬上限 |
| maxMachinesPerNode | 1024 | 每个机器节点可合并的机器数量上限 |
| offlineProcessingEnabled | true | 服务器是否允许已解锁且开启离线选项的产线离线运行 |
| recycleCapacityPerType | 2147483647 | 回收站每种资源容量，种类数固定 128 |

- 三个初始能量容量完全独立，默认来自 `EnergyCubeTier.ULTIMATE.getBaseMaxEnergy()`，不跟随 Mek 配置覆盖值。
- 玩家刚创建时三个池的储能都是 0。
- 上传普通能量物品给三池的最大容量分别增加该物品最大能量值，仍不上传物品当前能量；三池原有容量差值保留。
- 创造能量立方保留原有无限云端语义，仓库以 `Double.MAX_VALUE` 容量保存实际转移的有限能量。
- 初始产线数、机器节点额度和工作倍率若超过对应硬上限，创建新玩家时取较小值。
- 机器节点、产线和 workRate 扩容达到上限时返回拒绝，不消耗卡；最后一次扩容最多增加到上限。
- 本批不增加卡片单次增量配置，仍使用物品自身定义的增量。
- 能量容量允许 0，整数额度至少为 1；每节点合并量最大为 `Long.MAX_VALUE`。
- 回收站单类型容量范围为 1 到 `Long.MAX_VALUE / 128`，保证整个回收站数量总和不会溢出。

## runtime 分类

| 配置名 | 默认值 | 含义 |
| --- | ---: | --- |
| workerThreads | 0 | Runtime 工作线程数；0 为自动，手动范围 1 到 256 |
| checkpointIntervalTicks | 200 | 普通 Runtime 硬盘 checkpoint 间隔，范围 20 到 12000 tick |
| portTransferIntervalTicks | 200 | 上传和下载端口转移周期，范围 1 到 12000 tick |
| guiRefreshIntervalTicks | 20 | 打开云端 GUI 时的周期刷新间隔，范围 1 到 20 tick；1 为每 tick 刷新，20 为每秒一次 |

自动线程数维持原规则：按可用逻辑处理器数减 1，最少 2、最多 32。
普通 checkpoint 仍按玩家错峰；端口与终端的持久化事务不改成等待普通 checkpoint。
端口本地库存大小和能量缓存容量不在本批配置范围内。
GUI 刷新配置只影响稳态周期刷新，交互操作、编辑提交和错误反馈仍然事件驱动即时刷新；打开 GUI 后首个刷新仍在第 1 个服务器 tick 触发。
设为 1 时，每个打开的容器最多每 tick 请求一次周期 GUI 构建；现有单飞行限制防止任务堆积，实际完成频率取决于构建耗时，网络继续按变化节发送增量。降低间隔会提高 GUI worker 负载，不会改变硬盘 checkpoint 周期或端口转移周期。
产线画布的机器进度条在客户端按最近一次完整产线图采样的世界时间和渲染帧小数 tick 进行外推，仅对启用的 `RUNNING`/`DECAYING` 节点生效，并钳制在当前操作周期内；等待输入、等待能源、输出堵塞、就绪和关闭状态保持服务端采样值。仅更新仓库或总览的增量包不会重置进度采样时刻，新的产线图采样立即覆盖客户端预测。

## 编辑与保存

- 删除旧的“机器节点 + 特殊节点总共 4096”检查，只对机器节点应用玩家额度及服务器上限。
- 特殊节点和连线不设数量配置或玩法上限；产线输入 / 产线输出节点原有各一个的拓扑语义不变。
- 网络仍保留包字节安全限制和结构有效性校验，列表长度按实际剩余字节验证，避免恶意长度分配。
- 双击放置、放置按钮、Shift 滚轮、直接上传和合并上传均检查合并机器数。
- 下调节点或合并量上限，不删除已保存的超限节点；允许保留或减少，但不能继续增长。
- 下调产线上限不删除原产线；下调 workRate 保留已解锁值，实际运行使用配置上限，调回配置后可恢复原倍率。
- 下调回收站容量保留已有资源，超过新容量的类型不再接受新增；不会读取时截断或拒绝旧内容。
- 改动三池初始容量只影响新玩家。旧存档的云端容量不重置，缺少独立仓库容量字段的旧记录按原云端容量补全。
- 服务器配置通过 Mek 模组配置包同步给客户端；worker 只访问服务器启动时发布的不可变参数快照。
