# 云工坊三阶段实现记录

日期：2026-10-15

## 第一阶段：回收机兜底

已完成。

- 回收机和回收工厂的注册配方优先。
- 未命中注册配方时，任意非空物品按本体 `RecyclerRecipe.DEFAULT_OUTPUT`
  和 `RecyclerRecipe.DEFAULT_CHANCE` 进入临时兜底。
- 兜底每次消耗一个物品，允许零产出。
- 冻结路径新增 codec-only 的任意物品输入契约，不把通配条目混入注册配方表。
- Runtime 仍使用现有资源分配、概率抽取、产出倍率、操作预留和 checkpoint。
- 默认产出和概率直接读取 Mek 回收机常量，没有复制字面值。
- 单机和工厂均启用兜底。

## 第二阶段：升级 GUI

已完成。

- 新增 `GuiCloudSupportedUpgrades`，复用 Mek 支持条背景和遮罩布局。
- 支持条使用 `CloudworksUpgradeItems.currentStack`，与自定义升级物品保持一致。
- 云端升级窗口移除本体 `GuiSupportedUpgrades`，不再出现主列表和支持条图标不一致。
- 节点升级窗口改为：
  - 左侧：产线未指定升级余额；
  - 中间：当前节点指定数量；
  - 右侧：分配／释放操作；
  - 底部：按机器策略显示支持类型遮罩。
- NONE 和单轴机器的支持条会正确遮罩。
- 节点升级的记账、撤销／重做、等待节点禁用和服务端事务没有改变。

## 第三阶段：团队终端

核心共云终端、团队端口、权限链和解散回收流程已实现。

- 新增团队终端物品。
- 新增团队上传口和团队下载口。
- 直接使用 FTB-Library-Legacy 的 `ForgeTeam`、`ForgePlayer`、`Universe`
  和 `FTBLibAPI`，没有反射。
- 团队云使用 `teamId + 持久化 team UID` 生成虚拟 owner UUID，队伍删除后重建不会复用旧云。
- 团队云与个人云完全分开，复用现有 owner 域、Runtime、端口记录和持久化流程。
- 团队终端不要求玩家启用个人云端 capability。
- 团队访问通过队伍成员关系和持久化访问覆盖层控制，队长不能撤销自己的访问。
- 主界面增加团队 tab，可查看成员并提交访问开关。
- 任一成员在线时维持团队 Runtime 会话；成员全部离线时按团队云离线规则处理。
- FTB 队伍删除事件会关闭团队 Runtime 会话并停止团队云，保留数据，不自动删除。
- 团队端口使用现有输入／输出缓存和 QIO 升级体系，只把 owner 绑定到团队虚拟 owner。
- 新增团队离线卡和团队属性卡镜像。
- 无限资源卡在副手持有团队终端时写入团队云。
