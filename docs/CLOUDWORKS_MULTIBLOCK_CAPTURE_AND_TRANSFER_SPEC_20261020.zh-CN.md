# CloudWorks 多方块结构扫描、蓝图与传输方案

日期：2026-10-20  
状态：设计定稿，待实现  
适用范围：Mekanism 工业蒸汽涡轮、聚变反应堆、热力蒸馏塔、裂变反应堆、超临界移相器、热力锅炉及后续可注册的多方块结构

## 1. 设计结论

CloudWorks 的多方块结构采用“世界结构扫描 + 云端结构复制”的模式：

- 玩家在世界中正常搭建并成型 Mekanism 多方块结构。
- 玩家手持扫描机右键已成型结构。
- 扫描机只读取结构本身，不拆除世界方块。
- 扫描机拥有独立物品库存，用于放置上传材料。
- 材料满足结构组成后，扫描机可以把结构上传到云端。
- 世界中的真实结构保持不变，继续独立运行。
- 云端生成一个独立的多方块结构节点，按照理想环境从初始状态运行。

扫描机同时提供三个能力：

1. 捕获真实多方块结构；
2. 保存多方块结构蓝图；
3. 使用自身库存中的材料上传或下载云端结构。

多方块结构不归入环境节点、辅助节点或普通输入输出节点，而是机器节点的一种结构化变体。

## 2. 与现有系统的边界

当前普通机器缓存保存的是“物品模板 + NBT 变体 + 数量”，适合普通机器、升级和带 NBT 的机器物品。

多方块不是单个 `ItemStack`，而是以下内容的组合：

- 结构尺寸；
- 方块布局；
- 控制器和结构角色；
- 端口；
- 叶片、线圈、冷凝器、燃料组件等数量；
- 由结构计算出的容量、并行和参数。

因此多方块不能直接塞进现有 `CloudworksMachineCache`，也不能沿用普通机器的逐件下载逻辑。多方块应使用独立的结构资产记录，并在产线中表现为带结构快照的机器节点。

现有产线蓝图 `CloudworksBlueprint` 保存的是机器节点、输入输出节点、辅助节点和连线，不直接保存三维结构。多方块蓝图需要独立的 `CloudworksMultiblockBlueprint` payload，但可以复用现有蓝图库的文件、权限、导出码和分页框架。

## 3. 结构数据模型

扫描后生成不可变的 `MultiblockStructureSnapshot`。快照只描述结构，不保存运行中的资源状态。

建议字段：

```text
MultiblockStructureSnapshot
├─ schemaVersion
├─ multiblockType
├─ controllerIdentity
├─ dimension
├─ width / height / depth
├─ orientation
├─ blockPalette
├─ relativeBlockLayout
├─ componentRoles
├─ ports
├─ derivedParameters
├─ structureFingerprint
└─ adapterVersion
```

`componentRoles` 保存结构语义，例如：

- casing；
- controller；
- port；
- turbine blade；
- coil；
- condenser；
- fuel assembly；
- control rod；
- solar panel；
- superheater。

方块布局使用方块调色板加相对坐标保存，不重复保存每个方块的完整 NBT。结构指纹由规范化后的结构类型、尺寸、方向、方块布局、角色数量和端口配置生成。

结构指纹不包含：

- 世界坐标；
- 玩家 UUID；
- 团队 UUID；
- 当前产线 UUID；
- 当前燃料、流体、气体和能量；
- 热量、温度、运行进度；
- 损伤、辐射和事故状态。

## 4. 扫描机

扫描机是可携带的物品，拥有类似便携终端的独立库存和 GUI。扫描机库存不是玩家背包的别名，必须由服务端单独校验和持久化。

扫描机至少包含：

- 结构扫描入口；
- 三维结构预览；
- 结构材料库存；
- 扫描快照状态；
- 当前上传或下载会话令牌。

扫描机不应把完整结构快照直接写入物品 NBT。较大的结构快照由服务端会话保存，物品 NBT 只保存必要的会话令牌、结构资产 ID 或蓝图 ID。关闭 GUI、丢弃扫描机或会话超时后，未提交的临时会话自动取消。

### 4.1 扫描入口

玩家右键已成型多方块结构的控制器、外壳、端口或其他结构方块时，服务端执行：

1. 找到所属的 Mekanism 多方块控制器；
2. 检查结构已经成型；
3. 确认玩家有权读取该结构；
4. 根据多方块类型选择对应的捕获适配器；
5. 读取结构位置、尺寸、端口和语义组件；
6. 生成结构快照和材料需求；
7. 向客户端打开三维查看 GUI。

服务端读取 Mekanism 的成型结构数据。客户端不能自行扫描世界并提交方块清单。

### 4.2 扫描机库存

扫描机库存只接受当前结构类型允许的组成方块。服务端根据结构快照生成需求：

```text
工业蒸汽涡轮：
- 涡轮外壳 × 120
- 涡轮叶片 × 28
- 线圈 × 7
- 冷凝器 × 4
- 蒸汽端口 × 1
```

库存中的物品可以按任意顺序放置，服务端按规范化后的物品身份聚合数量。物品的非法 NBT、错误元数据和不属于该结构的方块不能被计入需求。

扫描机库存材料是云端上传所需的独立材料成本。世界中的真实结构不会被拆除，也不会自动变成扫描机库存。

## 5. 三维结构 GUI

扫描 GUI 是客户端三维预览界面，服务端提供只读结构投影。

界面建议包含：

- 中央三维结构视图；
- 旋转、缩放和镜像控制；
- 分层查看；
- 显示或隐藏内部方块；
- 结构类型和尺寸；
- 方块总数；
- 组件角色统计；
- 端口统计；
- 材料需求；
- 扫描机库存中的已放置数量；
- 蓝图保存按钮；
- 上传按钮。

三维预览使用简化的方块盒、角色颜色和端口标记，不调用真实世界 TileEntitySpecialRenderer，也不要求通过 `IBakedModel` 渲染完整方块。材料列表中的物品图标可以继续使用普通物品渲染路径。

大结构使用调色板、分层数据和压缩传输。`17×18×17` 结构有 5202 个位置，不能在每次点击时发送完整方块 NBT。服务端应限制最大尺寸、最大体积和最大快照字节数。

## 6. 上传云端

上传不改变世界结构，只消耗扫描机库存中的结构材料。

建议使用两次确认：

### 第一次确认：锁定并预校验

服务端检查：

- 扫描快照仍然有效；
- 世界结构仍然成型；
- 当前结构指纹与扫描指纹一致；
- 扫描机库存满足所有材料需求；
- 玩家或团队拥有目标云端权限；
- 目标云端和产线仍然存在；
- 当前没有重复的提交会话。

第一次确认只创建材料预留，不扣除物品，不创建可见的云端节点。

### 第二次确认：提交上传

服务端在同一持久化事务中：

1. 再次校验扫描快照和扫描机库存；
2. 预留并扣除扫描机库存材料；
3. 写入多方块结构资产；
4. 生成带结构快照的机器节点；
5. 将节点加入目标产线或目标云端机器缓存；
6. 完成事务。

上传失败时，扫描机库存必须完整恢复，不能生成半个结构节点。

如果世界结构在两次确认之间被改动，上传应拒绝并要求重新扫描。世界结构本身不会因为上传而被锁定或拆除。

## 7. 理想环境运行规则

云端多方块只复制结构，不复制世界运行状态。生成云端节点后：

- 热量从默认初始状态开始；
- 燃料为空；
- 流体和气体缓存为空；
- 能量为空；
- 运行进度为空；
- 损伤和辐射为初始安全状态；
- 不继承原结构的压力、转速、温度或余热；
- 使用 CloudWorks 的理想环境和已声明的热力合同。

结构参数仍然有效。例如：

- 涡轮叶片和线圈数量影响效率；
- 裂变燃料组件数量影响并行和容量；
- 蒸馏塔高度影响处理参数；
- 锅炉结构尺寸影响容量；
- SPS 端口和外壳影响可用合同。

后续升级、辅助节点和环境节点继续通过统一机器模块 API 生效。

## 8. 多方块蓝图

扫描完成后可以选择“保存为多方块蓝图”。保存蓝图：

- 不扣除扫描机材料；
- 不创建云端机器节点；
- 不影响世界结构；
- 不保存扫描机库存；
- 不保存运行状态。

蓝图内容使用独立的 `CloudworksMultiblockBlueprint`：

```text
CloudworksMultiblockBlueprint
├─ exporter
├─ name
├─ exportTime
├─ snapshot
├─ materialRequirements
├─ schemaVersion
└─ adapterVersion
```

蓝图可以重复使用，用于：

- 在投影器中生成三维幽灵结构；
- 显示结构材料需求；
- 作为多人或团队建造模板；
- 和真实世界结构进行结构指纹比较；
- 在满足材料后创建云端多方块节点。

蓝图不绑定世界坐标、原结构 UUID 或原产线 UUID。原结构被拆除、移动或改变后，蓝图仍然可以独立存在。

现有产线蓝图仍然只负责产线拓扑，不把三维结构直接塞入 `CloudworksLineDraft`。两种蓝图可以共用导出码、文件库和权限框架，但 payload 和校验器必须分开。

## 9. 多方块下载

普通机器继续使用现有终端下载：

- 普通点击下载一个机器；
- Shift 点击下载当前变体允许的最大堆叠；
- 目标是终端机器输出槽。

多方块不能沿用这个路径。多方块下载应使用扫描机作为目标：

```text
终端选择多方块结构资产
→ 放入扫描机作为下载目标
→ 显示结构快照和组成方块
→ 检查扫描机库存空间
→ 一次性下载完整结构包
```

多方块下载包包括：

- 结构快照；
- 结构蓝图信息；
- 外壳、端口、叶片、线圈、冷凝器等组成方块。

下载必须是完整原子操作：

- 所有组成方块都能写入扫描机库存时才允许执行；
- 空间不足时整个操作失败；
- 不允许只下载一部分结构组件；
- 云端结构资产只有提交成功后才扣减；
- 下载失败时云端资产和扫描机库存都不变。

下载蓝图和下载结构材料是两个动作：

| 动作 | 结构快照 | 组成方块 | 云端资产 |
| --- | --- | --- | --- |
| 下载蓝图 | 写入扫描机 | 不下载 | 不扣减 |
| 下载结构 | 写入扫描机 | 完整下载 | 扣减或移除 |

如果多方块节点仍被产线占用或正在运行，结构下载应拒绝。只有未被领取、未持有在途操作的结构资产才能被下载。

## 10. 结构资产与缓存

多方块应使用独立的结构资产记录，而不是普通 `CloudworksMachineCache`：

```text
MultiblockStructureAsset
├─ assetId
├─ structureType
├─ snapshot
├─ blueprintId
├─ availableCount
├─ claimedCount
├─ owner
└─ team
```

同一个结构指纹可以合并数量；不同结构尺寸、端口、组件数量或方向必须保持为不同变体。

结构资产的领取状态应和产线节点绑定。产线领取结构资产后，普通终端不能下载；节点删除或回收时，结构组件进入对应玩家或团队的回收路径。

## 11. 建议 API

建议新增以下公共接口或内部服务：

```text
CloudworksMultiblockCaptureType
CloudworksMultiblockCaptureAdapter
MultiblockStructureSnapshot
MultiblockComponentRequirement
CloudworksMultiblockBlueprint
CloudworksMultiblockAsset
CloudworksStructureUploadReservation
CloudworksStructureDownloadReservation
```

捕获适配器至少提供：

```text
canCapture(world, position)
capture(world, controller)
validate(snapshot)
requirements(snapshot)
compile(snapshot)
```

其中 `capture` 只在服务端主线程读取真实结构；`compile` 将结构快照转换成 CloudWorks 的机器注册、配方、端口、热力和模块合同。Runtime 只读取冻结后的结果，不访问世界或真实 TileEntity。

## 12. 数据和安全边界

- 所有扫描和上传请求必须在服务端验证；
- 客户端不能提交任意方块布局、端口数量或结构指纹；
- 结构尺寸、体积、方块数量和快照字节数必须有上限；
- 结构材料必须使用规范化身份比较；
- 自定义方块只能通过注册的捕获适配器进入结构；
- 扫描会话、上传会话和下载会话必须使用一次性令牌；
- 重复点击只能得到同一个事务结果；
- 玩家和团队权限在扫描、上传和下载三个边界都要重新检查；
- 不能把世界坐标或实时 TileEntity 引用写入云端 Runtime。

## 13. 实现顺序

建议按以下阶段实现：

1. 注册多方块捕获适配器和结构快照；
2. 扫描机右键识别已成型结构；
3. 只读三维结构 GUI；
4. 结构材料需求和扫描机库存；
5. 上传事务和云端结构资产；
6. 多方块蓝图保存、读取和投影；
7. 扫描机结构下载；
8. 接入 SPS、蒸馏塔和工业涡轮；
9. 接入锅炉、裂变和聚变的结构参数；
10. 补充团队结构资产、回收和蓝图权限。

第一阶段不实现运行状态迁移。所有云端结构从理想初始状态开始，避免把 Mekanism 的实时热量、燃料、流体、能量、损伤和辐射状态引入结构上传协议。
