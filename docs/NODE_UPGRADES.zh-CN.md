# 节点指定升级

更新：2026-10-15

## 使用

在产线编辑模式打开机器节点窗口，点击“节点升级”。
速度、能量可以分别选择共享或指定；默认均为共享。

1. 先通过原有产线升级窗口安装升级，形成产线未分配余额。
2. 将需要单独控制的轴切换为指定。
3. 左侧选择升级类型，点击分配；Shift 一次分配到余额或节点上限。
4. 右侧选择升级类型，点击释放；Shift 释放该类型全部指定数量。
5. 切回共享会将此轴指定数量释放到产线未分配余额。

这些操作只修改本地草稿，可撤销／重做；确认编辑时与其他产线配置一并提交。
等待放置的蓝图节点不可分配。观察模式只能查看节点分配信息。

## 记账

每轴满足：

```text
产线安装总量 = 所有节点指定数量之和 + 产线未分配余额
云端升级总资产 = 云端池 + 所有产线安装总量
```

节点字段：

| 值 | 含义 |
| --- | --- |
| `-1` | 参与本轴共享，存量节点默认值 |
| `0` | 指定模式、零升级，不参与本轴共享 |
| 正整数 | 指定数量 |

产线未分配余额不会再作用到已指定的轴。
指定和共享各自归一化后调用注册机器的 `MachineUpgradePolicy`，不重复叠加倍率。

例如两台相同机器，每台速度上限 8，产线安装速度升级 8：

- 全部共享：两台均按 `8 / 16` 的共享比例生效。
- 第一台指定 8：第一台按 `8 / 8`，第二台按 `0 / 8`。
- 第一台指定 0：第一台不享受速度升级，第二台按 `8 / 8`。

单节点内合并多台机器时，节点上限为合并数量乘每台机器的策略上限。
无升级策略容量为零，单轴策略只在相应轴生效。
Mek 配置／IC2 升级公式仍来自原有冻结配置，不增加第二套公式。

## 缩减与回收

- 机器数量减少：指定数量缩减到剩余机器可承载上限，释放量先回产线余额。
- 产线总上限不足：多出的安装数量退回云端升级池，与产线变更同事务提交。
- 删除节点：释放该节点指定；仍有其他机器容量时可保留为产线共享余额。
- 删除产线：返还整条产线安装总量，只返还一次。
- 卸载产线升级：只能卸载未分配余额，不能取走仍背书节点指定的升级。
- 指定配置改变：取消此节点现有操作并归还其输入预留，不提前发放产物。

配置收紧只会在原有编辑／归一化路径中处理额度及返还；
读档不会依据新上限静默丢弃存量升级。

## 蓝图

蓝图保存指定数量作为需求，产线安装总量不随导出复制。
放置时先使用目标产线已有余额，再从目标玩家的云端池安装差额。
机器或升级不足时整组等待：机器数量为零，不先扣升级。

等待组单独保存期望的机器数量和指定升级需求。
补齐时同事务安装；取消只删除占位，不返还未扣取的升级。
可用量在服务端重新校验，蓝图不是物品或升级的所有权凭证。

## 开发边界

- 存档：`MachineNodeData` 的可选 `assignedSpeed`／`assignedEnergy`。
- 协议：`CloudworksLineDraft.Machine` 同名字段；草稿蓝图结构版本为 4。
- 旧节点缺少字段时保持共享；既有支持的蓝图版本 1／3 按对应布局解码。
- 校验／额度：`CloudworksUpgradeLimits`。
- 原生效果：`CloudworksUpgradeEffects.Context.forNode`；自定义模块由 `onPreWork` 在操作规划时提供贡献。
- 提交：原有 `CloudworksPlayerDataManager.commitLineEdit` 事务，不新增逐按钮云端修改接口。
- 物品：仍由 `CloudworksUpgradeItems` 定义上传、下载及 GUI 的速度／能量物品。

速度和能量仍是原生共享/指定计数轴；外部模组通过 `MachineModuleType.custom(..., module)` 与 `CloudworksAPI.registerMachineModule` 增加节点模块。
模块实现 `ICustomMachineModule<MODULE>`，通过 `IMachineModule<MODULE>` 读取机器、来源、产线、分支及安装数。配方/端口由 `onRecipes` 返回不可变 `RecipeContribution`；运行倍率、概率和成本由 `onPreWork` 返回 `WorkContribution`；完成输出由 `onPostWork` 链式改写。
旧自定义数值回调、机制变换回调、完成策略接口和辅助效果解析器已经移除。详见[统一模块 API](CLOUDWORKS_MACHINE_MODULE_API.zh-CN.md)。没有逐 Tick 的附属回调。
