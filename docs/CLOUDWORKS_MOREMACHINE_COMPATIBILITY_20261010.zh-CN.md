# MoreMachine 可选兼容

日期：2026-10-10。

## 加载方式

- 对照 Mek 的 `MekanismHooks`，使用 `Loader.isModLoaded` 和独立兼容入口。
- `CloudworksHooks` 只在检测到 `mekceumoremachine` 后调用兼容类；入口使用 `@Optional.Method`。
- 所有 MoreMachine 类引用集中在 `common/integration/moremachine`，直接调用公开 API，没有反射。
- 模组依赖顺序增加可选的 `after:mekceumoremachine`，不增加必需模组。
- 注册发生在 `FMLLoadCompleteEvent`、云工坊注册表冻结之前。此时 MoreMachine 的 `postInit` 已完成，矿物列表已经填充。
- 开发依赖 JAR 不打包进云工坊产物。生产环境未安装 MoreMachine 时跳过兼容注册。

等级机器覆盖 BASIC / ADVANCED / ELITE / ULTIMATE 四个等级；三个复制器使用原生单机身份。

三个环境发电机族及等级燃气发电机还要求安装 `mekanismgenerators`。
同时补上 Mek 原生放射性废料桶，复用相同衰变合同；不计入上述 MoreMachine 数量。

## 身份和参数

- NBT 等级机器只把 `tier` 作为身份。缺少等级字段时归一化为 BASIC。
- 旋转凝缩机忽略 `mekData.mode`，只以 `tier` 区分等级；无需在真实世界切换方向后重新上传。
- 仅复制选中的嵌套 NBT 字段，不把 `mekData` 下的库存、能量、安全设置整个纳入身份。
- metadata 等级机器通过 MoreMachine 的 `MachineType.getValidMachines()` 和 `getStack()` 注册。
- 并行数量使用 MoreMachine `MachineTier.processes` 的 3 / 5 / 7 / 9。
- 基础能耗和储能读取原生配置；缓存容量和基础周期对照对应机器代码。
- 节点合并后由 Runtime 按机器数量放大并行数和容量，升级仍使用云工坊产线升级体系。
- 按本次需求不实现特殊线程升级；原物品在机器缓存中仍保留其 NBT。

## 虚空矿物采集机

- 直接读取 `VoidMineralGeneratorUitls.getCanOre()` 的结果，不另行重写矿辞、黑名单或反转规则。
- 候选模板复制后归一化为单个物品；候选重复项仍保留，维持原列表的随机权重。
- 一个物理机器周期仅抽取一种矿物，然后按等级的 `processes` 数量产出。
- 虚空矿物机的 Runtime `threads` 为 1，等级数量体现在单次产物数量上；不把能耗错误乘以等级并行数。
- 输出缓存为原机器 81 个输出槽的基础容量，即 `81 * 64`。
- 原生候选表只在加载阶段读取；worker 只处理资源 ID、数量和随机数，不访问 World、TileEntity 或矿辞。
- 新增互斥随机产物合同，不使用“每种矿物独立概率产出”的近似。
- 随机结果进入 Runtime operation 后保持到完成，沿用既有持久化的产物承诺，不在完成时重抽。

## 复制器

- `CONFIGURATION` 端口是模板输入，和普通 `INPUT` 分开存储；无需达到配方模板数量，只要对应类型存在即可。
- 一个模板缓存只允许一种资源身份；要换模板先清空机器缓存，旧模板和普通缓存一起进入回收站。
- 模板不参与配方预留或扣减。气体模板和 UU 为同一种气体时也分别计量，只有 UU 输入被消耗。
- 配方描述、冻结匹配、Runtime 数值编译、checkpoint、节点删除、产线删除和客户端缓存窗口均包含模板。
- 周期读取原生 `ticks`；每 tick 能耗为原生基础配置加上配方 `extraEnergy`，然后应用产线升级、合并数量、并行数和 workRate。
- 在途操作保存未缩放的附加能耗，重启后继续扣费；worker 不回调原生配方。

## 废料桶

- 主线程冻结放射性气体资格、原生衰变黑名单、周期及衰变量。
- 原生桶每个周期清除配置数量；等级桶每个周期清除 `配置数量 * processes * 10`，原生单桶衰变量上限为 `Integer.MAX_VALUE`。
- Runtime 再按合并机器数与 workRate 放大清除量，最后不足一批时只清除剩余数量。
- 不接受普通气体；可存放黑名单中的放射性气体，但不推进其衰变。
- 不扣能量，不生成产物，不创建配方预留；暂停节点停止衰变，进度保存到 checkpoint。
- 不模拟真实世界的辐射泄漏、邻接方块或向下输出。

## workRate 提升卡与默认能量

- 新增 `cloudworks:cloud_work_rate_upgrade_card`，右键成功后 workRate 加 1、消耗一张，持久化后使 Runtime 重新编译。
- 玩家未激活、存储不可用或达到整数上限时不消耗。
- workRate 放大配方操作数、基础及附加能耗、燃料消耗与发电、环境发电及废料衰变量，不增加机器身份的原生线程升级。
- 新玩家三池初始储能为 0，初始容量可分别配置，默认各为 Ultimate 能量立方基础容量 128 MJ；已保存玩家的储能与容量不重置。
- 收货仓、云端、发货仓独立保存各自上限，普通能量物品上传给三池增加相同的容量，保留初始差值。
- 扩容不增加任何储能；端口本地缓存仍为 512 GJ。
- 端口转移、Runtime、checkpoint 与主界面和产线能量罐使用同一份玩家容量数据；配置细则见 `CLOUDWORKS_CONFIGURATION_20261010.zh-CN.md`。
- 创造云端的仓库容量以 `Double.MAX_VALUE` 表示，仓库内仍只保存实际转移的有限能量。

## 本批未接入

| 机器或能力 | 原因 |
| --- | --- |
| 等级电动泵 | 涉及真实 World 流体探测与抽取，尚无云端环境合同 |
| 无线充电 / 无线能量设备 | 操作真实方块和实体，不属于纯云端生产节点 |
| 原机器自身的特殊线程升级 | 用户明确要求暂不实现 |
| 其他配方动态额外能耗 | 复制器已实现；原生电解配方的独立 `energyUsage` 尚未单独编译 |

未接入的设备没有注册成能运行的云端机器；已接入机器仍不覆盖表中的特殊线程升级及电解配方动态额外能耗。
基础参数及矿物清单在本次加载时冻结；修改相应配置后应重新启动以重新注册。
等级燃气发电机按用户要求复用现有云工坊燃气合同，不另外改写燃烧余量机制。
此文件不代表 MoreMachine 全部行为已经覆盖。
